Scamper Language Reference

This page describes every form built into the Scamper language: the fifteen reserved words, which cannot be used as names, and the bracket spellings that go with them. Everything else — +, map, circle — is an ordinary procedure, and lives in the function documentation instead.

A form here is not a procedure. if chooses a branch without evaluating the other one, so it cannot be passed to map or stored in a variable the way + can.

One rule runs through the whole page: a body is exactly one expression. A lambda, a let, a cond clause and a match clause each take a single expression, never a sequence. Scamper has no implicit begin and no definitions inside a body; use begin or let when several steps are wanted.

Notation

names

NAME
MODULE.NAME

A name may use any characters except whitespace, brackets, a quote, a semicolon, a period, and &, so null?, <= and string->list are all ordinary names. The fifteen reserved words on this page are the exception: they cannot be defined or used as a variable. A name containing a single period is a qualified name, whose first half is the alias given by a two-argument import and whose second half is a name that module exports. Exactly one period is allowed, and a qualified name may only be referred to, never defined. 

(import image img)
(display (img.circle 25 "solid" "red"))

literals

42   -0.3   1e3          ; numbers
#t   #f                   ; booleans
#\a  #\space              ; characters
"Hello"                   ; strings

A string may contain the escapes \a, \b, \t, \n, \v, \f, \r, \e, \", \' and \\; any other backslash simply stands for the character after it. Hex (\x41;), Unicode (\u0041) and octal (\101) escapes are not supported and are reported as errors. 

(display (list 42 -0.3 #t #\a "a\tb"))

;

; TEXT

A semicolon comments out the rest of the line. That is the only kind of comment: there is no block comment and no datum comment. 

; Adds one to its argument.
(define add-one (lambda (x) (+ x 1)))

Statements

import

(import MODULE)
(import MODULE ALIAS)

Brings a module's exported names into scope. With an alias, the names are not brought into scope; each is reached as ALIAS.NAME instead. The module is named bare: a string there names a file to load, so (import "image") looks for a file called image and fails. 

(import image)
(import music mus)

define

(define NAME EXPR)

Binds NAME to the value of EXPR. A definition is a statement, so it may only appear at the top level of a file — never inside a lambda or a let. 

(define x (+ 1 1))

define-export

(define-export NAME EXPR)

A define that also exports NAME, exactly as if it were followed by (export NAME). Only meaningful in a file that another file imports. 

(define-export square (lambda (x) (* x x)))

export

(export NAME ...)

Names which of this file's definitions another file may import. A file with no export statement exports nothing, and several export statements add up. 

(define square (lambda (x) (* x x)))
(define cube (lambda (x) (* x x x)))
(export square cube)

display

(display EXPR)

Shows the value of EXPR in the output. It is a statement rather than a procedure, so it appears at the top level of a file and never inside another expression. An expression written on its own at the top level is shown too, so display is mostly a way of saying so explicitly. 

(display "Hello!")

struct

(struct NAME (FIELD ...))

Declares a new kind of value. It defines a constructor NAME, a predicate NAME?, and a getter NAME-FIELD for each field. A struct value also matches the constructor pattern (NAME PAT ...). 

(struct person (name age))
(define alice (person "Alice" 30))
(display (person-age alice))

Expressions

procedure call

(EXPR EXPR ...)

Evaluates every sub-expression left to right, then calls the first on the rest. Parentheses always mean a call unless the first word is one of the reserved words on this page, so (1 2 3) is an attempt to call 1 rather than a list; build a list with list. 

(display (max 1 2 3))

lambda

(lambda (NAME ...) BODY)

An anonymous procedure with the given parameters. BODY is exactly one expression. 

(define hypotenuse (lambda (x y) (sqrt (+ (* x x) (* y y)))))
(display (hypotenuse 3 4))

&

(lambda (NAME ... & REST) BODY)

An & in a parameter list marks the last parameter as the rest parameter: it collects every remaining argument into a list, so the procedure accepts any number of them. (lambda (& xs) ...) collects all of them. 

(define sum-all (lambda (& xs) (apply + xs)))
(display (sum-all 1 2 3 4))

if

(if EXPR EXPR EXPR)

Evaluates the first expression; if it is #t, the second is the answer, and otherwise the third. Both branches are required, and only the one taken is evaluated. 

(display (if (> 3 2) "bigger" "smaller"))

cond

(cond [EXPR EXPR] ...)

Tries each clause's first expression in turn and answers with the second expression of the first clause whose test is #t. else is an ordinary binding whose value is #t, so a final [else ...] clause catches everything left. A cond in which no clause matches is an error. 

(display (cond [(= 1 2) "one"] [(= 2 2) "two"] [else "neither"]))

and

(and EXPR ...)

#t when every expression is #t. It stops at the first #f, leaving the rest unevaluated — which is why it is a form rather than a procedure. (and) is #t. 

(display (and (> 2 1) (< 2 3)))

or

(or EXPR ...)

#t when at least one expression is #t. It stops at the first #t, leaving the rest unevaluated. (or) is #f. 

(display (or (> 1 2) (< 1 2)))

begin

(begin EXPR EXPR ...)

Evaluates each expression in order and answers with the last. At least two are required, since a single expression needs no begin. It is how a body holds several steps when the earlier ones are run for their effect. 

(display (begin (+ 1 1) (* 3 3)))

let

(let ([PAT EXPR] ...) BODY)

Binds each pattern to the value of its expression and evaluates BODY — exactly one expression — with those bindings in scope. Note the parentheses around the whole list of bindings. Every binding is in scope throughout every binding's expression as well as the body, which is Scheme's letrec, so two procedures bound by one let may call each other and there is no need for a let*. The left of a binding is a full pattern rather than only a name, so a binding can take a value apart. 

(display (let ([x 10] [y 20]) (+ x y)))
(display (let ([(cons x rest) (list 1 2 3)]) rest))
(display
  (let ([even2? (lambda (n) (if (= n 0) #t (odd2? (- n 1))))]
        [odd2? (lambda (n) (if (= n 0) #f (even2? (- n 1))))])
    (even2? 10)))

match

(match EXPR [PAT EXPR] ...)

Tries each pattern against the value of the first expression and answers with the expression beside the first pattern that matches, with that pattern's names bound. A value that matches no pattern is an error. 

(display (match (list 1 2 3) [null "empty"] [(cons h t) h]))

[...]

[EXPR ...]

A vector literal, whose elements are evaluated left to right. Square brackets are not interchangeable with parentheses: they mean a vector everywhere except in the fixed [PAT EXPR] positions of let, match and cond. 

(display (vector-ref [1 2 3] 0))

{...}

{KEY VALUE ...}

A map literal, read as alternating keys and values; an odd number of elements is an error. Keys and values are both ordinary expressions. Curly braces mean this and nothing else. 

(display {"name" "Alice" "age" 30})

#(...)

#(BODY)

A shorthand for a lambda. Its parameters are the % names appearing in BODY: % (or %1) is the first argument, %2 the second, and %& collects the rest. The arity is the largest %k that appears. BODY must be a parenthesized expression, and the # must touch the opening parenthesis. 

(display (map #(* % %) (list 1 2 3)))

??

??

A hole: a placeholder for an expression not written yet. A program containing one still parses and runs, and reaching a hole raises "Hole encountered in program!" — so (if #t 1 ??) is 1, and a procedure whose body is a hole is fine until it is called. It is written bare, with no parentheses of its own. 

(define area (lambda (r) (* 3.14 ??)))

Patterns

patterns

_                      ; matches anything, binds nothing
NAME                   ; matches anything, binds NAME to it
42  #t  #\a  "hi"      ; matches exactly that value
(NAME PAT ...)         ; matches a struct or list built by NAME
[PAT ...]              ; matches a vector of exactly that many elements

A pattern appears on the left of a match clause and on the left of a let binding. (cons h t), (person n a) and null take apart a non-empty list, a struct and the empty list respectively. 

(display (match [1 2] [[a b] (+ a b)] [_ 0]))

What Scamper does not have

These are Scheme and Racket habits with no Scamper spelling. Reaching for one is reported as an error, never silently taken to mean something else.

  • let* — let already binds its names letrec-style.
  • quote and the ' shorthand — build a list with list.
  • set! — a variable is never reassigned; a vector or map is changed with its own procedures.
  • macros: define-syntax and syntax-rules.
  • named let, do, and case.
  • when and unless — use if or cond.

The longer list of differences from Scheme is kept in docs/DIFFERENCES.md.
